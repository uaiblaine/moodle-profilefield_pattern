### Details

**1. Privacy export.**
- `moodle_content_writer::export_data()` writes `data.json` at the same subcontext on every call.
- A user with two or more pattern fields therefore exports only the last one.
- Core's `profilefield_text` has the identical loop.
- The existing test uses a single field.
- Fix: one subcontext per field (`[pluginname, shortname]`), and a test with two fields.

**2. Locked field blocks every profile save.**
- How it happens:
  - For a frozen field, `exportValues()` returns the value the form loaded.
  - `profile_validation()` validates that value, and the user cannot edit it.
- How a stored value comes to fail the rules:
  - the admin changed the mask, regex or check digit after values were stored;
  - or the value was written by `profile_save_custom_fields()`.
- Fix: skip pattern validation when the field is locked for this user, mirroring core's test
  (`is_locked() && !has_capability('moodle/user:update', system)`). Add a test.

**3. Stale rows after a settings change.**
- Effects on uniqueness:
  - `forceunique` compares the new shape with old rows, so a duplicate can be stored.
  - Report filters miss rows stored in the other shape.
- Options:
  - refuse to change these settings while `user_info_data` has rows for the field;
  - or re-normalise the stored values when the definition is saved (an adhoc task above a few
    hundred rows).

**5. Missing tests.**
- No test covers `edit_field_set_locked()`.
- No test covers the signup path (`signup_validate_data`).
- No test shows that a `null` from `convert_external_data()` is not saved.
- The uniqueness test covers only one direction (masked stored, raw typed).
- No test covers a rejection on mask or length on the no-validation paths.

**6. `masked_text_element` outside the `api`.**
- Options:
  - expose the element type through `api`;
  - or declare `form\masked_text_element` public in the dependency.

**9. Validation cost in `customfield_pattern`.**
- `mask::apply()` processes every character of a value of any length before `maxlength` is
  checked.
- A multi-megabyte value through a web service costs linear time and memory.
- Fix in the dependency: check the length first.

## Fleet template (outside this plugin)

`moodle-dev/templates/ci.yml` sets `cancel-in-progress` to false only for `main`. Once a plugin has
`MOODLE_*_STABLE` branches, a push there can cancel the previous push's run.
